# 小米 17 Pro Max 背屏：调研结论和最小原型

调研时间：2026 年 11 月。**我没有这台手机，下面的原型没有在真机上跑过。**

## 结论

1. **没有找到小米给第三方开放的背屏接口。**
   能上背屏的第三方应用（微信、飞书、外卖、打车等）是小米逐家适配的系统卡片，不是应用自己把画面画上去。
   普通应用直接在背屏上打开窗口会被 HyperOS 拦下。
2. **有一条社区摸出来的路能走通，但需要 ADB 权限。**
   背屏在系统里是第二块显示（编号 1）。HyperOS 拦的是「在背屏上启动」，没有拦「把已经在主屏上运行的窗口挪过去」。
   所以做法是：先在主屏启动一个窗口，再用 shell 权限执行
   `am display move-stack <任务编号> 1`。
   shell 权限有两个来源：电脑上的 adb（数据线），或者手机上的 Shizuku（每次重启手机要重新启动一次）。
3. **这条路只适合自己玩，不适合发给普通玩家。**
   它依赖 USB 调试或 Shizuku，小米系统更新随时可能堵上，锁屏时限制更多。
   要做成正式功能，只能等小米开放接口，或者去申请成为适配的合作应用。

## 依据（都是社区项目的说明，不是小米官方文档）

- [Back Screen Studio](https://github.com/Peter23687/Xiaomi-17-Pro-Max-rear-screen-customizability)：
  说明了「先在主屏启动、再用 `am display move-stack <task> 1` 挪过去」的做法；
  实测背屏 976×596，摄像头盖住左边 296 像素；
  不保持亮屏的话，大约 10 秒后小米自己的背屏程序（`com.xiaomi.subscreencenter`）会把时钟换回来。
- [Mi Back Screen](https://github.com/totallynotkasai/mi-back-screen)：
  同样用 Shizuku 执行 `am` / `input` 命令；提到锁屏时 HyperOS 只允许自家应用在背屏启动，所以要先在主屏打开再挪；
  背屏每次变暗时小米的背屏程序会把自己的界面拉回来。在 HyperOS 3.0.319 的 17 Pro Max 上测过。
- [MiRearUltra](https://github.com/muratgorel55/MiRearUltra)：把背屏当作 Display #1，用安卓的 Presentation 接口加 Shizuku。

游戏里摄像头区域的宽度已经按上面实测的 296 改了（`src/config.ts` 的 `backScreen.cameraArea`）。

## 原型做了什么

- **网页部分（已经在游戏里，网页版也能看）**：地址以 `#back-screen` 结尾时，整个页面只画 976×596 的背屏画面，
  左边 296 像素留黑。它只读存档，自己把时间补算出来再画；点宠物是摸摸，点名字那一行换一只；
  宠物回家时显示明信片 12 秒。点击会先记下来，由主屏那边的游戏写进存档。
- **安卓部分（默认没有装进工程）**：`prototypes/back-screen/BackScreenActivity.java`，一个单独的窗口，打开的就是上面那个地址，并保持亮屏。
- **电脑端脚本**：`send-to-back.sh`（Mac / Linux）和 `send-to-back.ps1`（Windows），启动这个窗口、找到任务编号、挪到显示 1。

安卓部分默认不装进工程，是因为我没法编译验证：万一有错，会连累普通版也打不了包。

## 怎么试

前提：已经按 `docs/安卓打包步骤.md` 把普通版装到手机上并能正常玩，手机开着 USB 调试、连着电脑。

1. 把原型装进安卓工程，重新打包安装：

   ```
   node prototypes/back-screen/enable.mjs
   npm run android
   ```

   然后在 Android Studio 里点 Run ▶。

2. 确认 adb 能用（Android Studio 自带，在 SDK 的 `platform-tools` 文件夹里；提示找不到命令的话，把这个文件夹加进系统的 PATH，或者用完整路径）：

   ```
   adb devices
   ```

   列表里出现你的手机就对了。

3. 先在主屏正常打开一次游戏，然后运行脚本：

   ```
   sh prototypes/back-screen/send-to-back.sh                                              # Mac / Linux
   powershell -ExecutionPolicy Bypass -File prototypes\back-screen\send-to-back.ps1        # Windows
   ```

4. 把手机翻过来看背屏。想收回：同一个脚本后面加 `home`。

5. 不想要了：`node prototypes/back-screen/enable.mjs off`，再重新打包。

## 可能遇到的情况（都是推测，要试了才知道）

| 现象 | 可能的原因 |
| --- | --- |
| 脚本说没找到任务编号 | `am stack list` 在这个系统版本上的输出格式和我预想的不一样。按脚本的提示手动找编号 |
| `move-stack` 没报错，但背屏没变化 | 背屏的显示编号不是 1。运行 `adb shell dumpsys display`，找 976×596 的那块屏的编号，改脚本里的 `REAR` |
| 显示几秒后变回小米的时钟 | 小米的背屏程序抢回去了。社区项目的做法是保持亮屏，或者停掉 / 重启 `com.xiaomi.subscreencenter`，这一步我没有做 |
| 画面方向或比例不对 | 背屏窗口的实际尺寸和 976×596 不一致。截图发我，我按实际尺寸调 |
| 背屏上的画面不动 | 主屏的游戏在后台时不会存档；背屏画面是自己补算的，理论上不依赖主屏，如果不动说明页面没跑起来 |
| Android Studio 编译报错，提到 BackScreenActivity | 原型的代码有问题。先运行 `enable.mjs off` 恢复普通版，把报错发我 |

## 如果原型能跑，下一步可以做的

- 用 Shizuku 代替数据线，在游戏里加一个「显示到背屏」的开关（参考上面两个开源项目，Back Screen Studio 是 Apache-2.0 许可）。
- 处理小米背屏程序抢回显示的问题。
- 按实机截图调整摄像头避让区域和排版。
